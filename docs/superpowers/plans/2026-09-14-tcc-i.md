# TCC I (Bloco C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dar ao aluno o meio de entregar o trabalho escrito de TCC I — o modelo
`Submissao` (PDF + editável, uma linha por `Projeto`) e a tela para enviá-lo e
reenviá-lo — com o orientador enxergando o que foi entregue, sem nenhuma
transição de status de `Projeto`.

**Architecture:** Um modelo novo (`Submissao`) no app `apps/projetos`, que já
existe desde o Bloco B. Um serviço (`enviar_submissao`) cria-ou-atualiza a
única linha por projeto. Uma tela nova para o aluno; a tela de orientações do
Bloco B ganha uma extensão para o professor ver o que foi enviado.

**Tech Stack:** Django 5, PostgreSQL, `django-storages` (S3/MinIO) para o
arquivo, mesmo padrão de `Usuario.foto`.

**Spec:** `docs/superpowers/specs/2026-09-14-tcc-i-design.md`

## Global Constraints

- Todo identificador de código em português (CLAUDE.md).
- Regra de negócio só em `services.py`/`permissions.py`; `models.py` só
  campos, `Meta`, `__str__`; `views.py` sem regra (CLAUDE.md §4).
- Toda checagem nova provada por mutação, nunca só pela suíte passando; uma
  checagem vizinha pode mascarar a ausência da checagem nova — mutar e olhar
  a saída, nunca inferir cobertura pela suíte verde (CLAUDE.md, "Disciplina
  de Testes").
- Toda citação de arquivo:linha conferida no momento em que é escrita, não
  copiada de memória (CLAUDE.md, "Disciplina de Testes").
- `Projeto.status` permanece `EM_ANDAMENTO` ao fim deste plano — nenhuma
  tarefa avança o ciclo de vida (spec §3.1).
- Reenviar substitui a entrega atual; não há histórico de versões anteriores
  (spec §3.2).
- PDF e editável são obrigatórios juntos; `.pdf` só no campo `pdf`, `.docx`
  só no campo `editavel` (spec §3.3, §4.1).
- Sem ação do orientador sobre a submissão neste bloco — só visibilidade
  (spec §3.4).
- `TAMANHO_MAXIMO_UPLOAD_MB = 15` (`config/settings.py`, já existe).
- Lookup de `Projeto` sempre escopado ao aluno autenticado
  (`get_object_or_404(Projeto, pk=..., aluno=request.user)`), nunca um 403
  depois de buscar por pk cru — mesmo padrão que `apps/projetos/views.py::
  editar_tema` fixou no Bloco B, para não abrir um oráculo de existência.
- Se a suíte de acessibilidade reprovar uma tela nova ou alterada, o defeito
  é da tela — não afrouxe asserção, não reduza regra do axe, não exclua
  seletor. Rota nova entra em `ROTAS` (`conftest.py`), nunca numa suíte
  própria — já aconteceu duas vezes no Bloco B (T6, T9) de uma suíte isolada
  esconder um defeito de acessibilidade.

```python
from apps.comum.validators import valida_extensao_editavel, valida_extensao_pdf, valida_tamanho_arquivo


class Submissao(models.Model):
    """O trabalho escrito que o aluno entrega para a banca (Bloco C, spec
    §4.1) — uma linha por `Projeto`, não uma tabela de histórico: reenviar
    ATUALIZA esta mesma linha, substituindo os arquivos e incrementando
    `versao`. A versão anterior não fica acessível pelo sistema depois de
    substituída — decisão do usuário, ciente do custo (sem histórico para
    auditar depois de uma correção). Ver `services.enviar_submissao`.
    """

    projeto = models.OneToOneField(
        Projeto,
        # PROTECT: apagar o Projeto não pode arrastar a submissão em
        # cascata, mesmo raciocínio de Candidatura.aluno/OpcaoCandidatura.tema
        # no Bloco B.
        on_delete=models.PROTECT,
        related_name="submissao",
        verbose_name="projeto",
    )
    pdf = models.FileField(
        "PDF",
        upload_to="submissoes/",
        validators=[valida_extensao_pdf, valida_tamanho_arquivo],
    )
    editavel = models.FileField(
        "editável",
        upload_to="submissoes/",
        validators=[valida_extensao_editavel, valida_tamanho_arquivo],
    )
    versao = models.PositiveSmallIntegerField("versão", default=1)
    enviada_em = models.DateTimeField("enviada em", auto_now_add=True)
    atualizada_em = models.DateTimeField("atualizada em", auto_now=True)

    class Meta:
        verbose_name = "submissão"
        verbose_name_plural = "submissões"

    def __str__(self):
        return f"{self.projeto} — versão {self.versao}"
```

```python
@transaction.atomic
def enviar_submissao(projeto, por, pdf, editavel):
    """Registra o envio (ou reenvio) do trabalho escrito de `projeto` (Bloco
    C, spec §5). Cria a `Submissao` na primeira chamada; nas seguintes,
    ATUALIZA a mesma linha (substitui `pdf`/`editavel`, incrementa `versao`)
    — não existe histórico de versões anteriores (spec §3.2, decisão do
    usuário, custo aceito).

    GARANTIA que esta função entrega, e só esta: `por` é exatamente o aluno
    de `projeto` (`permissions.pode_enviar_submissao`), e `projeto.status`
    é `EM_ANDAMENTO` no momento da chamada. Ela NÃO garante nada sobre uma
    corrida entre dois reenvios simultâneos do mesmo aluno — não há
    `select_for_update` aqui, porque o recurso (a `Submissao` de UM projeto)
    não é disputado por partes concorrentes do sistema do jeito que vagas de
    professor são: só o próprio aluno escreve nesta linha, e duas abas do
    mesmo aluno reenviando ao mesmo tempo é uma corrida de baixíssimo risco
    (o pior caso é a versão que perder a corrida ficar como se nunca tivesse
    sido enviada — sem corrupção de dado, só uma versão a menos do que o
    aluno esperava).
    """
    permissions.garante(
        permissions.pode_enviar_submissao(por, projeto),
        "Você só pode enviar a submissão do seu próprio projeto.",
    )
    if projeto.status != Projeto.EM_ANDAMENTO:
        raise ValidationError(
            "Este projeto não está mais em andamento — não é possível enviar ou "
            "reenviar a submissão."
        )

    submissao, criada = Submissao.objects.get_or_create(
        projeto=projeto, defaults={"pdf": pdf, "editavel": editavel}
    )
    if not criada:
        submissao.pdf = pdf
        submissao.editavel = editavel
        submissao.versao += 1
        submissao.save(update_fields=["pdf", "editavel", "versao", "atualizada_em"])
    return submissao
```
